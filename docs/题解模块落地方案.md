# KECE 题解模块落地方案

更新：2026-11-05 · v4。状态：交互 Demo 已认可；后端数据与接口基础已实现，前端页面和正式联调尚未完成。

按已确认的方向实施：**用户打开 Markdown 编辑页，写完直接发布；修改后直接更新。没有审核流程。** 本版保留 v3 的简单产品范围，并细化接入位置、数据约束、开发批次、验收和上线顺序。此前 v1/v2 的审核、分步提示和复杂版本设计不再适用。

## 1. 使用流程

题目详情 → 题解列表 → 写题解 → 填标题和 Markdown 正文 → 发布题解 → 立即公开。

- 第一版支持算法题 ALGO、数据库题 DB，客观题继续使用现有答案解析。
- 登录用户可以发布，不要求先 AC，不限制一人一题只能写一篇。
- 列表按发布时间倒序，显示标题、作者、时间，复用分页；修改文章不改变首次发布时间。
- 阅读页直接显示完整 Markdown 内容，代码按代码块展示，无提示解锁或二次展开流程。
- 本人可编辑、删除自己的题解；修改成功后读者立即看到新内容。
- 管理员可在发布后隐藏不适合公开的内容，这是事后管理，不是发布前审核。官方标记以后按需要补充，不额外增加发布流程。

## 2. 编辑页

页面只保留：关联题目、标题输入框、Markdown 编辑区、预览切换和「发布题解」按钮。编辑已有文章时，按钮改为「更新题解」。

沿用已认可 Demo 的编辑/预览切换，保持 KECE 的黑白、直角风格。以现有 MarkdownEditor 和 renderMarkdown 为基础补齐能力，支持代码块、表格、链接和公式；首版不另做并排编辑模式。

输入编辑、预览和阅读均支持代码语法高亮，按 fenced code 的语言标识解析 Python、C/C++、Java、SQL、JavaScript/TypeScript；未标注或不支持的语言回退为纯文本。复用项目已安装的 Prism/Monaco 能力，不增加发布步骤。

标题非空且不超过 80 字；正文非空且不超过 64 KiB UTF-8，前后端同时校验。点击发布直接发送，不再弹投稿检查页。

提交期间按钮禁用；失败保留全部输入并允许重试，成功跳转到题解详情。未发布输入只保留在当前页面，离开前提示，首版不建设服务端草稿、自动保存或历史修订系统。

首版不做导读、提示字段、评论、点赞、附件上传、审核后台和站内通知。

### 后台：题解管理

在管理后台侧栏增加「题解管理」，首版仅 ADMIN 可访问；教师管理权限留到后续。这里管理已发布内容，不出现待审核、通过审核或退回投稿。

- **筛选区**：标题/作者关键词搜索、独立题号输入（精确匹配）、题型（全部/算法/SQL）、状态（全部/已发布/已隐藏）。题号相同时按题型区分；修改筛选回到第 1 页，复用每页 20 条及跳页组件。
- **横向列表**：标题、关联题目（题型 + 题号 + 名称）、作者、更新时间、状态、操作。按更新时间倒序、ID 倒序排列；默认不展示已删除内容，不增加无实际用途的统计卡片。
- **查看**：点击标题或「查看」展开页内全文区，保留当前筛选与列表，关闭即可继续管理；展示题目关联、作者、发布时间及 Markdown 全文，代码高亮与前台一致。窄屏同样使用全宽详情，不挤压列表列宽。
- **隐藏/恢复**：已发布行显示「隐藏」，已隐藏行显示「恢复公开」。操作直接生效，无审批；隐藏后即使作者修改正文也不能自动公开。恢复前服务端确认题目仍存在且公开、文章未删除。
- **删除**：二次确认中显示文章标题，确认后软删除；取消不修改数据。首版不提供批量删除。隐藏可附简短原因，原因不是必填审核意见。
- **反馈状态**：操作中禁用当前按钮，成功后更新该行；失败保留列表并提示重试。空结果提供清空筛选，读取失败与空列表区分。

后台列表和全文示例仅用于交互演示，演示中的隐藏、恢复、删除不操作生产数据。

## 3. 一张数据表

新增 solution 表：

| 字段 | 用途 |
| --- | --- |
| id、question_type、question_id | 文章及关联题目；题型和题号共同定位，避免 ALGO/DB 题号冲突 |
| author_id、title、content_md | 作者、标题、原始 Markdown 正文 |
| status | PUBLISHED / HIDDEN，创建成功即 PUBLISHED |
| version | 乐观锁序号，只用于防止多窗口覆盖，不是内容版本库 |
| client_request_id、request_hash | 创建请求幂等键，按作者唯一；服务端保存首次创建内容的 SHA-256 指纹，超时重试不重复发文 |
| last_management_reason | 可空，记录最近一次管理员隐藏的简短原因，不新增审核或审计流程表 |
| created_at、updated_at、deleted_at | 发布时间、更新时间、软删除时间 |

列表索引：(question_type, question_id, status, deleted_at, created_at, id)；作者索引：(author_id, created_at, id)。不增加修订表、审核表或举报流程表。

同一创建幂等键、同一请求指纹重试返回原文章及其当前状态；题目、标题或正文不同则返回冲突。request_hash 创建后不变，不能用文章修改后的正文判断原始请求是否重复。所有变更都带 version，成功后递增；冲突提示用户重新读取并保留本地文字，不自动覆盖。

## 4. 接口

沿用 /api/v1 与现有 ApiResponse；以下省略前缀。

| 接口 | 用途 |
| --- | --- |
| GET /solutions?questionType=ALGO&questionId=1&page=1&size=20 | 题目下的公开题解列表 |
| GET /solutions/{id} | 读取详情；隐藏内容仅本人/管理员可查看 |
| POST /solutions | 登录用户直接发布，authorId 取当前身份 |
| PUT /solutions/{id} | 本人修改，携带 version；不允许修改题目、作者和状态 |
| DELETE /solutions/{id}?version=1 | 本人或管理员软删除，带当前 version |
| GET /me/solutions | 当前用户的题解列表及编辑入口 |
| GET /admin/solutions?keyword=&questionId=&questionType=&status=&page=1&size=20 | ADMIN 管理列表；关键词匹配标题/作者，题号精确匹配，支持题型、发布/隐藏状态及分页；不返回正文 |
| PATCH /admin/solutions/{id}/status | ADMIN 隐藏/恢复，携带 version；隐藏可带 reason，写入 last_management_reason |

隐藏文章即使由作者修改也保持 HIDDEN，不能通过普通更新解除隐藏。已删除文章不能再更新或恢复为公开。

管理员删除复用 DELETE /solutions/{id}，首版不增加删除原因输入；隐藏原因仅在管理员状态接口接收。所有管理操作在服务端校验 ADMIN 身份，不能只靠菜单隐藏。

## 5. 必要的实现规则

- 公共列表和详情同时检查：题目存在且公开、文章 PUBLISHED、未删除。题目转私有或删除后，公共题解立即不可读。
- 私有题不允许公开发布题解；课练口令和考试上下文不赋予题解发布/阅读权限。本人可查看自己曾发布的正文，但不因此获得私有题面、题名或标准答案，关联位置显示「题目当前不可用」。
- JWT 验证登录身份，服务端校验所有权；不能依赖前端隐藏按钮实现权限。管理员恢复仍需检查题目公开状态。
- Markdown 预览与阅读使用同一净化规则，禁止脚本和危险链接；不执行正文中的代码，不自动读取 SQL 标准答案或他人提交。
- 先直接使用 MySQL 索引查询，列表不加载正文，作者信息批量查询；无需新增 Redis 正文缓存、消息队列或搜索服务。
- 返回作答页不自动填入题解代码，不覆盖已有作答草稿。接口失败或版本冲突时保留编辑内容。

## 6. 页面落位与导航契约

题解入口放在具体题目内，阅读、写作沿用前台侧栏；个人主页负责本人管理，后台负责内容管理。不新增全站「题解广场」。

| 页面 | 路由约定 | 接入方式 |
| --- | --- | --- |
| 算法题题解列表 | `/questions/:id?tab=solutions&page=1` | 现有题目详情增加「题目 / 题解(n)」切换，标题区和作答入口保留 |
| 数据库题题解列表 | `/database/:id?tab=solutions&page=1` | 与算法题共用列表组件，传入 DB 和题号 |
| 写题解 | `/solutions/new?questionType=ALGO&questionId=4` | 只填写标题、正文；关联题目从路由确定，提交时服务端再次校验 |
| 阅读题解 | `/solutions/:id` | 全文、作者、关联题目、返回列表和作答入口；本人显示编辑、删除 |
| 编辑题解 | `/solutions/:id/edit` | 从详情回填正文与 version；题目关联只读 |
| 我的题解 | `/profile?tab=solutions&page=1` | 仅本人主页出现此页签；不扩展其他用户的隐藏内容入口 |
| 后台题解管理 | `/admin/solutions` | ADMIN 专属路由及侧栏项，筛选、分页、页内全文和管理操作 |

导航行为：

1. `router/index.ts` 增加懒加载页面；前台页面放在 DefaultLayout 下，后台页面放在 AdminLayout 下。题解写作路由设置 requiresAuth，后台设置 ADMIN；直接访问 URL 同样受保护。
2. 阅读、编辑页保留确定的返回来源：题目列表或本人列表及其页码；只接受已知来源值，不接受任意外部 returnUrl。刷新后仍能定位关联题目，缺失来源时回到该题的题解列表。
3. 从题集、课练进入时，仅透传已知的 `setId/itemId/practiceCode/pqId`，用于返回和作答。题解 API 不接收这些参数作为访问授权；独立考试路由不增加题解入口。
4. 私有题即使可通过课练口令查看，也不展示公共题解入口。公开题目参与课练时仍按公开题规则读取；隐藏入口不能替代服务端校验。
5. 列表页码写入 URL；发布成功返回列表时重新读取，数量来自同一分页响应的 total。加载失败不伪装成「0 篇」；删除当前页最后一条后回退到有效页码。
6. 题型、题号、页码变化时刷新对应数据，并取消或丢弃旧请求结果；只切换题目/题解页签不重复加载题面。
7. 返回作答仅执行路由跳转。保留现有代码草稿键 `kece:code_draft:q_{id}_{language}` 和 SQL 草稿键 `kece:sql_draft:q_{id}` 的行为，不写入题解示例代码。

## 8. 编码前固定的数据与接口细节

### 8.1 数据约束

- `content_md` 使用 MEDIUMTEXT，应用层限制 65,536 个 UTF-8 字节，避免 TEXT 的字节边界与产品限制不一致。前端用 TextEncoder，后端按 UTF-8 编码长度校验。
- `title` 去除首尾空白后非空，最长 80 个 Unicode 码点；前后端口径一致，不仅依赖 HTML maxlength。正文只用空白判断是否为空，不擅自改写代码缩进。
- `client_request_id` 使用 UUID，建立 `UNIQUE(author_id, client_request_id)`；`request_hash` 使用固定长度 64 字符，保存服务端对固定字段顺序的创建 payload 计算的摘要。
- `version` 从 1 开始。创建后题型、题号、作者、幂等键和 request_hash 不可变。创建时间不因编辑、隐藏或恢复而改变。
- 在原列表索引之外，将本人查询索引明确为 `(author_id, deleted_at, created_at, id)`，后台默认排序索引为 `(deleted_at, updated_at, id)`。是否另加状态筛选索引以 EXPLAIN 和数据量为依据。
- 原算法题、数据库题目前均物理删除；不增加指向两种表的多态外键，不修改原题表删除方式。读取时检查关联源表；题目消失后保留作者已有正文，但公共接口不暴露内容。
- 列表只投影元信息，不查 content_md；列表与 count 使用一致的权限条件，不能先分页再在 Java 中过滤隐藏项。

### 8.2 DTO 与错误码

| 请求/响应 | 固定内容 |
| --- | --- |
| 创建请求 | `questionType, questionId, title, contentMd, clientRequestId` |
| 更新请求 | `title, contentMd, version`；不得携带可写的 authorId、questionId、status |
| 状态请求 | `status, version, reason?`；status 仅 PUBLISHED/HIDDEN，reason 最多 200 个码点 |
| 分页响应 | 复用 `list, total, page, size`，默认 20、最大 100；先用 long 校验 offset 范围再转现有参数类型 |
| 列表项 | `id, questionType, questionId, questionTitle, authorId, authorName, title, status, version, createdAt, updatedAt`，以及派生的题目是否可公开信息；无正文 |
| 详情 | 列表元信息 + `contentMd`；管理原因仅返回作者或 ADMIN，普通读者不获得内部字段 |
| 创建/更新/状态成功 | 返回最新详情和 version；前端以服务端返回状态为准，不自行假设一定公开 |

目前项目业务异常使用 **HTTP 200 + ApiResponse.code**，不是 HTTP 403/409。题解沿用现有协议：成功 200、参数 4001、未登录 4002、禁止操作 4003、不可读取 4004、系统错误 5000；新增 `CONFLICT=4009` 表示版本或幂等冲突。前端通过已有 ApiError.code 分支处理，本次不改写全站异常协议。

公开读取对不存在、已删除、无权查看的隐藏文章或私有题关联文章统一返回 4004。本人/管理员可读正文的例外按下一节执行。访问公开 GET 时失效 token 目前会被当作游客；所有写接口必须带登录要求，不能依赖可选身份解析。

### 8.3 可见性和状态

| 情况 | 公众 | 作者 | ADMIN |
| --- | --- | --- | --- |
| 公开题 + PUBLISHED + 未删除 | 可读 | 可读、编辑、删除 | 可读、隐藏、删除 |
| 公开题 + HIDDEN + 未删除 | 不可读 | 可读、编辑、删除；不能自行恢复 | 可读、恢复、删除 |
| 关联题私有或已删除 + 文章未删除 | 不可读 | 可读已有正文、编辑、删除；不展示受限题名/题面 | 可管理正文；不能恢复公开 |
| 文章已删除 | 不可读 | 不可读、不可改、不可恢复 | 首版不提供回收站或恢复 |

教师在题解管理中与普通登录用户相同，只能管理自己的文章。ADMIN 不通过普通更新接口代改他人正文。题目变私有不修改文章 status；题目重新公开后，原 PUBLISHED 文章恢复可读，原 HIDDEN 文章仍保持隐藏。

### 8.4 重试与竞争处理

1. 新建编辑页在首次发布时生成请求键，保存本次提交 payload。网络超时后保留同一键和 payload，以原请求重试；未确定结果前不生成新键再次发同一篇。可以继续编辑本地文字，但应先确认旧请求结果，再将新内容作为原文章更新。
2. 服务端以数据库唯一约束兜底。两个相同请求并发插入时，只产生一行；撞唯一键后按原 hash 比对。同键不同内容返回 4009，不当作系统错误。
3. 原文章已被编辑时，重试创建仍按不可变 request_hash 判断，返回原文章当前状态；原文章已删除时返回明确冲突，不能复活或补建。
4. 更新、隐藏、恢复、删除均使用 `WHERE id=? AND version=? AND deleted_at IS NULL`，成功时 version 加 1，并检查受影响行数。作者更新 SQL 不写 status。
5. 写入公开题解、恢复公开在事务中锁定并检查关联题目行，固定先题目后文章的锁顺序；普通正文编辑不更改公开性。公共读取仍实时判断关联题目，不使用可能过期的题面详情缓存。
6. 发生版本冲突，编辑页保留本地全文，展示「内容已在其他位置更新」并提供复制本地内容、读取最新版本。读取最新版本覆盖输入前须确认；不静默替用户合并或覆盖。
7. 题解读写失败不影响判题和其他页面。首版不增加正文缓存、异步写入、消息队列或全文搜索服务；日志只记录操作人、文章 ID、结果和耗时，不打印正文或 token。
