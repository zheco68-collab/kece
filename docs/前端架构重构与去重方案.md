## 1. 结论

采用「按业务归组、复用稳定逻辑、分批替换」的重构方式，继续使用 Vue 3、TypeScript、Pinia、Vue Router 和现有样式体系。

当前主要问题是同一行为散落在不同页面、页面同时承担太多职责，而不只是文件数量多。重构后文件数量可能增加，但修改一次分页、判题状态或下载错误处理，应能覆盖所有使用者。

优先顺序：请求与鉴权 → 查询分页 → 判题结果与轮询 → 大页面拆分 → 样式及残留清理。目录迁移跟随业务批次进行，不先全站搬家。

### 3.1 请求、登录刷新和文件下载（P0）

代码证据：

- `frontend/src/api/request.ts:64` 与 `:142` 在正常响应和 HTTP 异常响应中分别处理凭据刷新，存在相似但不一致的逻辑。

- `api/question.ts:95` 与 `api/exam.ts:293` 分别处理鉴权、fetch、Blob、临时链接和回收；还有直接拼接 token 下载 URL 的分支。

方案细化与落地方案：

1. **共享刷新 Single-flight Promise 与挂起死锁修复**：
   保留现有 `http.get/post/...` 调用接口，统一底层 `executeWithAuth`。
   ```typescript
   // 结构化刷新状态锁
   let refreshPromise: Promise<string> | null = null;
   let refreshSubscribers: Array<{ resolve: (token: string) => void; reject: (err: unknown) => void }> = [];

   async function getValidAccessToken(): Promise<string> {
     if (!refreshPromise) {
       refreshPromise = (async () => {
         try {
           const newToken = await authApi.refreshToken();
           refreshSubscribers.forEach(cb => cb.resolve(newToken));
           return newToken;
         } catch (err) {
           // 关键：逐一拒绝所有排队等待的并发请求，消除死锁 Promise
           refreshSubscribers.forEach(cb => cb.reject(err));
           // 触发全局登出与广播同步
           userStore.logout();
           notifyCrossTabLogout();
           throw err;
         } finally {
           refreshSubscribers = [];
           refreshPromise = null;
         }
       })();
     }
     return new Promise((resolve, reject) => {
       refreshSubscribers.push({ resolve, reject });
     });
   }
   ```
2. **多标签页跨 Tab 同步登出广播（BroadcastChannel / Storage）**：

3. **HTTP 状态与业务 Code 归一化**：
   所有错误包装为统一定义的 `ApiError`，携带 `status`（HTTP 状态码）、`code`（服务端业务码）、`message`。继续尊重项目 `code=200` 为成功。

1. **`usePagedQuery` 核心实现规格**：
   抽取 `shared/composables/usePagedQuery.ts`，严格控制单一职责：
   ```typescript
   export interface PagedQueryOptions<T, P> {
     fetcher: (params: P & { page: number; size: number }) => Promise<{ list: T[]; total: number }>;
     defaultParams?: P;
     defaultSize?: number;
     immediate?: boolean;
   }

   export function usePagedQuery<T, P extends Record<string, unknown>>(options: PagedQueryOptions<T, P>) {
     const page = ref(1);
     const size = ref(options.defaultSize ?? 20);
     const params = reactive<P>({ ...(options.defaultParams as P) });
     const list = ref<T[]>([]) as Ref<T[]>;
     const total = ref(0);
     const loading = ref(false);
     const error = ref<string | null>(null);

     let requestSeq = 0; // 自增请求序号，杜绝迟到响应串页（Race Condition 防御）

     async function load(targetPage?: number) {
       if (targetPage !== undefined) page.value = targetPage;
       const currentSeq = ++requestSeq;
       loading.value = true;
       error.value = null;
       try {
         const res = await options.fetcher({ ...params, page: page.value, size: size.value });
         if (currentSeq === requestSeq) { // 仅当是最新请求时采纳
           list.value = res.list;
           total.value = res.total;
           // 自动回退保护：删除最后一项后如果当前页超出最大页码，自动回退有效页
           const maxPage = Math.max(1, Math.ceil(res.total / size.value));
           if (page.value > maxPage) {
             load(maxPage);
           }
         }
       } catch (err: unknown) {
         if (currentSeq === requestSeq) {
           error.value = err.message || '加载列表失败';
         }
       } finally {
         if (currentSeq === requestSeq) loading.value = false;
       }
     }

     function reset() {
       page.value = 1;
       load();
     }

     if (options.immediate ?? true) load();

     return { page, size, params, list, total, loading, error, load, reset };
   }
   ```

1. **统一判题轮询控制器 `useSubmissionMonitor`**：
   抽取 `features/judging/composables/useSubmissionMonitor.ts`，基于链式 `setTimeout` 实现自适应、无重叠轮询：
   ```typescript
   export interface SubmissionMonitorOptions<T> {
     submissionId: Ref<number | null>;
     fetcher: (id: number) => Promise<T>;
     isTerminal: (result: T) => boolean;
     onSuccess?: (result: T) => void;
     intervalMs?: number; // 默认 1500ms
     maxTimeoutMs?: number; // 默认 120000ms（防无限挂起超时）
   }

   export function useSubmissionMonitor<T>(options: SubmissionMonitorOptions<T>) {
     const result = ref<T | null>(null) as Ref<T | null>;
     const polling = ref(false);
     const error = ref<string | null>(null);
     let timer: number | null = null;
     let activeId: number | null = null;

     const stop = () => {
       if (timer !== null) {
         clearTimeout(timer);
         timer = null;
       }
       polling.value = false;
     };

     const scheduleNext = () => {
       if (!polling.value) return;
       timer = window.setTimeout(async () => {
         if (!options.submissionId.value || options.submissionId.value !== activeId) return;
         try {
           const res = await options.fetcher(activeId);
           if (options.submissionId.value !== activeId) return; // 切换 ID 丢弃迟到响应
           result.value = res;
           if (options.isTerminal(res)) {
             stop();
             options.onSuccess?.(res);
           } else {
             scheduleNext(); // 只有本次请求返回后才安排下一次，绝对避免慢网络请求堆叠
           }
         } catch (err: unknown) {
           error.value = err instanceof Error ? err.message : '获取评测结果异常';
           stop();
         }
       }, options.intervalMs ?? 1500);
     };

     watch(options.submissionId, (newId) => {
       stop();
       result.value = null;
       error.value = null;
       activeId = newId;
       if (newId) {
         polling.value = true;
         // 立即首查一次
         options.fetcher(newId).then((res) => {
           if (activeId !== newId) return;
           result.value = res;
           if (!options.isTerminal(res)) scheduleNext();
           else { stop(); options.onSuccess?.(res); }
         }).catch(err => { error.value = err.message; stop(); });
       }
     }, { immediate: true });

     onBeforeUnmount(stop);

     return { result, polling, error, stop };
   }
   ```

   ```typescript
   export function useCodeDraft(options: {
     targetKey: string;     // 新规范 Key，如 kece:draft:${userId}:${type}:${questionId}:${lang}
     legacyKeys?: string[]; // 历史规范 Key 列表，如 ['kece:code_draft:q_1_cpp', 'kece:db_draft_1']
   }) {
     function getDraft(defaultValue = ''): string {
       const current = localStorage.getItem(options.targetKey);
       if (current !== null) return current;
       // 遍历旧 Key 回退探测
       if (options.legacyKeys) {
         for (const lk of options.legacyKeys) {
           const val = localStorage.getItem(lk);
           if (val !== null) {
             localStorage.setItem(options.targetKey, val); // 静默迁移至新键
             localStorage.removeItem(lk); // 清理旧键
             return val;
           }
         }
       }
       return defaultValue;
     }

     function saveDraft(code: string): void {
       if (!code) localStorage.removeItem(options.targetKey);
       else localStorage.setItem(options.targetKey, code);
     }

     function clearDraft(): void {
       localStorage.removeItem(options.targetKey);
     }

     return { getDraft, saveDraft, clearDraft };
   }
   ```

大页面拆分原则与落地方案：
1. **单一页面私有组件就近存放**：
   拆分出的子组件存放在各自业务目录下的子目录中（例如 `features/practice/components/detail/`），不提升到全局 `shared/`，避免破坏业务封装性。
2. **状态归属清晰**：
   页面根 View 充当编排协调者（Orchestrator），负责提供 props 与响应 events；非跨路由共享的数据一律不丢入全局 Pinia，只保存在页面专属的组合式函数（如 `usePracticeSession.ts`）内。
3. **客观题渲染与输入解耦**：
   当前已抽取 `features/questions/lib/objectiveAnswer.ts`，统一选项文本/字母、答案归一化和多选排序；继续保留三处页面各自的提交与自动保存时机。只有三处输入交互能够完全同构时，才引入受控 `ObjectiveInput.vue`，避免制造含大量场景开关的万能组件。
4. **计时器逻辑纯粹化 (`useCountdown`)**：
   抽离 `shared/composables/useCountdown.ts`：以服务端结束时间 `endTime` 与客户端对齐时间戳计算剩余秒数，不依赖 `setInterval` 简单 `-1`，杜绝浏览器切后台休眠带来的倒计时变慢或误差，支持 `durationMinutes === 0` 不限时场景。

建议抽取接口的范围：

| 模块 | 调用方提供 | 模块负责 | 不负责 |
| --- | --- | --- | --- |
| `usePagedQuery` | 查询参数、分页请求函数 | 异步状态、最新结果、重载、清理 | 列定义、删除/重判、权限 |
| `useQuestionCandidates` | 题型、关键词/题号、页码 | 三类候选查询、标准化身份与元数据 | 章节、分值策略、选中/取消规则 |
| `useSubmissionMonitor` | 当前提交 ID、读取结果函数 | 终态、进度、无重叠轮询、错误与清理 | 提交代码、考试计分、导航 |
| 草稿模块 | 稳定存储身份、内容、恢复策略 | 恢复/保存/重置与存储失败处理 | 交卷、后端自动保存策略 |

这几个模块已有多个真实使用场景，值得形成较小的公共 interface；无需再抽一层只有转发调用的万能业务 service。

## 4. 目标目录与依赖规则

以下为目标示意，按批次创建实际需要的目录，不一次生成空壳：

```text
frontend/src/
  app/
    router/                # 路由组装、权限守卫
    layouts/               # 前台/后台布局与导航
  features/
    questions/             # 三类题目、管理页、检索候选
    judging/               # 提交状态与结果监控
    solutions/             # 题解阅读、写作、管理
    practice/              # 课练会话、榜单、管理
    exams/                 # 考试场次、答卷、组卷
    problem-sets/          # 题集编排与学习进度
    profile/               # 个人主页
    home/                  # 首页演示与练习入口
  shared/
    http/                  # HTTP、刷新、二进制下载
    ui/                    # 分页、表格、对话框等通用 UI
    composables/           # 无业务归属的可复用状态逻辑
    lib/                   # Markdown、纯格式化等基础能力
    styles/                # token、reset、公共样式
    types/                 # PageResult 等真正通用的契约
```

业务目录内部按需要放置 `pages/components/composables/api.ts/types.ts`，小模块可直接用少量文件，不强制层层套目录。

依赖方向：`app → features → shared`。`shared` 不导入业务页面；不同 feature 只使用显式开放的能力，例如考试可调用 judging 的结果监控，不能访问另一个 feature 的页面私有状态。两处出现相似代码后才考虑公共接口，不预先造插件框架。

迁移规则：

1. 保留现有路由 URL、name、query、角色配置与懒加载；隐藏管理菜单只是体验，权限依然由后端校验。
2. 每个业务批次先整理逻辑，再以独立可审查变更移动文件和更新 import。类型跟随所属业务，公共 `PageResult` 等留共享目录。
3. `types/index.ts`、旧 API 文件可临时定向 re-export，记录剩余调用；迁移完成删除兼容出口，不能长期存在两份实现。
4. 避免大而全的 `export *` 入口让首页间接加载 Monaco 或所有业务页面。Monaco/Prism 分包必须做生产构建后的冷启动验证。
5. 路由表拆成前台/后台/考试等静态分组；守卫独立测试。导航元数据可共享名称和权限，但导航结构不必机械等同于路由结构。

## 5. 样式和死代码清理规则

继续保留当前黑白、直角、白底代码块的视觉风格。本次结构重构不同时重设计 UI。

- 先整理现有 `style.css` 的 token、基础元素、通用按钮/输入框、正文排版；明确一个视觉规则的所有者。
- 页面只保留布局和专用样式；先用一对页面验证共享按钮、筛选栏、状态提示，再逐页替换。
- 不把各页面的 `.header/.title/.panel` 直接搬成全局同名选择器，避免覆盖关系变化；可以使用组件作用域或业务前缀。
- `AdminLayout.vue:484` 附近使用深层选择器与 `!important` 覆盖页面类名，布局壳和业务页面已经耦合。先将重复的页面头/筛选栏样式迁移到有明确所有权的组件，再逐条移除覆盖；不能先删覆盖让布局失效。
- 重复颜色、字号和间距先归并为语义变量；确实有不同语义的危险操作、主按钮与次按钮保持区别。
- 保留用户已经确认的掉落动画、乱码复原、减少动态效果偏好，以及 100% 缩放下检索器的滚动与分页可见性。

可直接验证的样式试点：全局 `style.css:366`、`:384` 与算法/考试结果页的 loading 样式；`AdminQuestionsView.vue:251` 与 `AdminDbQuestionsView.vue:224` 一带的页面头、筛选和操作区域。先比较 DOM、尺寸、状态语义，再决定共用组件或共享样式，不以 CSS 看起来相似作为唯一依据。

删除前使用「引用证据 → 路由/动态使用检查 → 构建与交互验证」流程。`questionApi.exportTestCasesZipUrl`、`downloadInputUrl`、`downloadOutputUrl` 已确认无调用，并因会把令牌拼入 URL 而移除；导出 ZIP 统一保留已鉴权的 Blob 下载。旧的 `AppHeader.vue` 也已确认不在路由、布局、显式 import 或自动组件注册链路中，并通过构建后删除；其余静态搜索候选仍须逐项确认动态 class、样式副作用、懒加载和类型声明，不能只凭文件名删除。
