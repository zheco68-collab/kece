# 前端架构重构与去重方案

日期：2026-11-06。状态：待实施方案。本轮只检查代码与运行现有单元测试，不修改业务实现、不部署。

## 1. 结论

采用「按业务归组、复用稳定逻辑、分批替换」的重构方式，继续使用 Vue 3、TypeScript、Pinia、Vue Router 和现有样式体系。

当前主要问题是同一行为散落在不同页面、页面同时承担太多职责，而不只是文件数量多。重构后文件数量可能增加，但修改一次分页、判题状态或下载错误处理，应能覆盖所有使用者。

优先顺序：请求与鉴权 → 查询分页 → 判题结果与轮询 → 大页面拆分 → 样式及残留清理。目录迁移跟随业务批次进行，不先全站搬家。

## 3. 已确认的优先改造点

### 3.1 请求、登录刷新和文件下载（P0）

代码证据：

- `frontend/src/api/request.ts:64` 与 `:142` 在正常响应和 HTTP 异常响应中分别处理凭据刷新，存在相似但不一致的逻辑。
- `request.ts:54` 的刷新失败处理只清空订阅数组；`:126` 为等待者创建的 Promise 没有在这个失败分支被 reject。代码检查提示并发请求可能一直等待，实施前必须用可重复测试确认并修复。
- `api/question.ts:95` 与 `api/exam.ts:293` 分别处理鉴权、fetch、Blob、临时链接和回收；还有直接拼接 token 下载 URL 的分支。

方案：

1. 保留现有 `http.get/post/...` 的调用形式；将刷新集中为一个共享 Promise（Single-flight 模式）。一次过期触发一次刷新，所有等待者同成功或同失败，失败后状态可恢复。
   ```typescript
   // 共享刷新单飞 Promise 模式：
   let refreshPromise: Promise<string> | null = null;
   async function getValidAccessToken(): Promise<string> {
     if (!refreshPromise) {
       refreshPromise = doRefreshToken().finally(() => { refreshPromise = null; });
     }
     return refreshPromise;
   }
   ```
2. 彻底修复 `request.ts:54` 刷新失败时未决议订阅者 Promise 的挂起隐患：在刷新失败的 catch 分支，逐个 reject 订阅队列中的等待者并清理，确保调用端能及时捕获异常并转跳登录，不留永久挂起的死 Promise。
3. 增加多标签页同步登出机制：当某一页面因 RefreshToken 过期或用户主动触发 `userStore.logout()` 时，通过 `BroadcastChannel` 或 `storage` 事件通知同源其他 Tab 同步清理登录态并定向至登录页，防止迟到的旧轮询或刷新请求在多 Tab 间引发竞争重刷。
4. HTTP 状态错误、业务 `code` 错误使用同一套归一化规则。继续尊重项目 `code=200` 的成功契约。
5. 提供统一下载能力：鉴权、超时、JSON 错误体识别、文件名解析、Blob URL 回收。预览 PDF 和下载文件保持各自交互。
6. 普通请求不引入自动重试 POST。仅在明确的认证失效契约下允许一次刷新重放，重判、交卷、发布题解的幂等语义保持不变。
7. 去除 URL token 前先验证服务端所有下载路由接受 Bearer 请求；大文件下载和新标签页预览单独验证，不机械替换。

验收：并发过期时只刷新一次；刷新失败所有调用方结束等待；退出登录期间不得因迟到刷新重新登录；下载失败不得把 JSON 错误页保存为 Zip。

### 3.2 搜索、分页和异步列表（P1）

代码证据：后台三类题目列表、用户/题集/公告列表重复维护 `rows/total/loading/error/page`、防抖和筛选重置；`AdminQuestionsView.vue:44` 已有请求序号防串页，`QuestionSolutionList.vue:22` 的加载逻辑没有同等保护。`RankingsView.vue` 则已有 URL 驱动查询，不能统一成丢失 URL 的本地状态。

方案：

- 先在算法题和数据库题后台列表验证 `usePagedQuery`，再推广。它只负责异步状态、最新请求生效、取消/失效、重载和分页结果；字段校验、列定义、删除权限仍由业务页面负责。
- 防抖与 URL 查询作为按需组合能力，不让一个 hook 同时接管表格、导航、权限、弹窗和业务动作。
- 每个页面只有一个明确的加载触发源，避免关键词 watcher 重置 page 后又触发第二次加载。
- 删除最后一条时回退有效页；快速搜索 A→B 后，即使 A 较晚返回，也不能覆盖 B。
- 复用现有 `DataTable.vue` 和 `Pagination.vue`，不再制造第二套通用表格/分页组件。

验收：三类后台题目筛选结果不变；题号精确查询、关键词、防抖、空状态、失败重试和删除回页正确；排名 URL、浏览器前进后退行为保留。

组卷候选检索也是这一批的重要复用点：`admin/ExamEditView.vue:74` 与 `admin/PracticeEditView.vue:87` 的三题库加载、标签切换、防抖和候选映射近似；已有 `components/problem-sets/QuestionPicker.vue:24` 具备分页、`#ID` 查询、竞态保护和卸载清理。

当前考试/课练候选加载还只取第一页 100 条。迁移到分页检索可以解决这一实际限制，但它属于明确的行为改进，应单独写验收用例，而不是声称完全等价搬迁。

从现有 QuestionPicker 抽取 `useQuestionCandidates` 检索内核，供题集、考试和课练的选择界面使用。候选统一携带题型、ID、标题、必要评分元数据，联合键使用题型+ID。题集的章节目标与单一题型限制、考试的添加操作、课练的选择/取消操作及分值策略保留在各自编排页面；不直接把三套页面替换成同一个大选择器。

标准化候选实体类型接口定义（解决当前分页与元数据不统一限制）：
```typescript
export interface StandardCandidate {
  uniqueKey: string;     // 标准复合主键 `${type}_${id}`，避免 ALGO 和 DB 题号重叠冲突
  id: number;
  type: 'ALGO' | 'DB' | 'OBJECTIVE';
  title: string;
  subType?: string;      // 针对客观题细分: SINGLE / MULTIPLE / JUDGE / FILL
  difficulty?: string;   // EASY / MEDIUM / HARD
  defaultScore?: number; // 题库默认分值，供组卷赋分预填
}
```

### 3.3 判题状态、结果呈现和轮询（P1）

代码证据：`QuestionResultView.vue:31`、`DatabaseQuestionResultView.vue:31`、`ExamQuestionResultView.vue:25`、`ExamDbQuestionResultView.vue:24` 重复声明终态；现有 `utils/submission.ts` 已包含终态判断、语言、默认代码、状态文字和内存格式化。四个结果页还分别实现定时轮询。

方案：

- 首先复用已有状态定义，不另建第二份状态表。显示文案允许有明确的展示模式，但业务终态只有一个来源。
- 将生命周期管理集中到 `useSubmissionMonitor`：当前请求结束后再安排下一次；终态停止；切换提交 ID 丢弃旧结果；卸载停止计时；网络失败可见且可重试。
- `useSubmissionMonitor` 统一覆盖所有使用场景：不仅服务于 4 个独立结果页，也要作为 `PracticeDetailView.vue`（课练会话）及未来题集内联作答的通用轮询驱动源，彻底消除课练页面内手工手写 `setInterval`/`pendingJudgePollTimer` 的轮询逻辑。
- 数据读取通过明确的适配函数接入普通算法、普通 SQL、考试算法、考试 SQL 的现有接口；URL 和权限仍在各自业务模块。
- 普通结果页与考试结果页共享状态摘要、进度、测试点列表；SQL 表格结果、算法内存/耗时和考试成绩披露规则保持独立。
- 慢请求时不得叠加请求。隐藏标签页降频可作为独立优化，但考试截止与保存流程不能随之停止。

验收：4 个结果页的成功/失败/终态一致；慢请求不重叠；路由切换不显示上一次提交；考试页保留考试条目的身份与内容优先级，不通过公共接口绕过成绩可见性规则。

### 3.4 返回上下文、草稿与编辑器（P1/P2）

题集、课练、普通刷题页面重复组装 `setId/itemId/practiceCode/pqId`；可抽出白名单参数解析与返回地址生成，避免遗漏上下文。考试场次使用单独的上下文模型，不能与普通题目路由混用。

编辑器继续使用 `CodeEditor.vue`；草稿存取、默认代码和未保存状态从页面移到所属业务模块。草稿键要明确账号、题型、题目或考试场次、语言，实施前设计旧草稿兼容策略，不能改完 key 后让用户原草稿消失。

草稿前向迁移与兼容规范：
- 抽取草稿管理工具时，提供双键回退机制（新规 Key 优先，未命中读取 legacyKey 并静默转存至新规 Key，随后清理旧 Key）。
- 算法题旧规范 `kece:code_draft:q_${id}_${lang}` 与数据库题 `kece:db_draft_${id}` 须作为 fallback 读取源无缝过渡，防止重构发版导致正在刷题的学生正在编辑的代码被清空。

必须保留的业务差异：考试恢复时后端暂存与本地草稿的现有优先级；ACM 保存后评测、OI 暂存的区别；普通算法提交文件映射与 SQL 原文的区别；教师预览、已交卷、已结束课练可以出现普通刷题入口，但不得误绑定课练成绩。

考试题面当前是「考试条目 + 实时题面」的组合，不是完整的不可变题面快照。`examQuestionId` 与题库 `questionId` 不能互换；考试标题/分值、正文优先级与补充题库信息的规则需要保留，不能直接使用公共 Question DTO 替代。

Monaco 与 Markdown 阅读器属于不同能力，不合成万能编辑器。保留当前白底代码块、高亮、数学公式与 DOMPurify 清洗。`main.ts` 的 Prism 初始化、`monaco-setup.ts` 的语言和 worker 注册都具有副作用，不得因没有显式调用就删除。

客观题和计时分别处理：

- `ExamObjectiveView.vue:148` 目前多题共用一个自动保存 timer，快速跨题输入可能取消前一题的保存。先加跨题编辑复现用例，再以每题保存协调修复；该修复单独记录，不能误把已有风险当作需保留行为。
- 考试与课练计时可共享剩余时间计算和清理；保留课练 `durationMinutes=0` 不限时，以及各自的到期动作。推荐根据服务端截止时间计算而非只依赖 interval 自减，验证切后台和重新同步。榜单刷新、自动保存不并入倒计时模块。

建议抽取接口的范围：

| 模块 | 调用方提供 | 模块负责 | 不负责 |
| --- | --- | --- | --- |
| `usePagedQuery` | 查询参数、分页请求函数 | 异步状态、最新结果、重载、清理 | 列定义、删除/重判、权限 |
| `useQuestionCandidates` | 题型、关键词/题号、页码 | 三类候选查询、标准化身份与元数据 | 章节、分值策略、选中/取消规则 |

| 草稿模块 | 稳定存储身份、内容、恢复策略 | 恢复/保存/重置与存储失败处理 | 交卷、后端自动保存策略 |

这几个模块已有多个真实使用场景，值得形成较小的公共 interface；无需再抽一层只有转发调用的万能业务 service。

## 4. 目标目录与依赖规则

以下为目标示意，按批次创建实际需要的目录，不一次生成空壳：

```text
frontend/src/
  app/
    router/                # 路由组装、权限守卫
    layouts/               # 前台/后台布局与导航
  features/
    questions/             # 三类题目、管理页、检索候选
    judging/               # 提交状态与结果监控
    solutions/             # 题解阅读、写作、管理
    practice/              # 课练会话、榜单、管理
    exams/                 # 考试场次、答卷、组卷
    problem-sets/          # 题集编排与学习进度
    profile/               # 个人主页
    home/                  # 首页演示与练习入口
  shared/
    http/                  # HTTP、刷新、二进制下载
    ui/                    # 分页、表格、对话框等通用 UI
    composables/           # 无业务归属的可复用状态逻辑
    lib/                   # Markdown、纯格式化等基础能力
    styles/                # token、reset、公共样式
    types/                 # PageResult 等真正通用的契约
```

业务目录内部按需要放置 `pages/components/composables/api.ts/types.ts`，小模块可直接用少量文件，不强制层层套目录。

依赖方向：`app → features → shared`。`shared` 不导入业务页面；不同 feature 只使用显式开放的能力，例如考试可调用 judging 的结果监控，不能访问另一个 feature 的页面私有状态。两处出现相似代码后才考虑公共接口，不预先造插件框架。

迁移规则：

1. 保留现有路由 URL、name、query、角色配置与懒加载；隐藏管理菜单只是体验，权限依然由后端校验。
2. 每个业务批次先整理逻辑，再以独立可审查变更移动文件和更新 import。类型跟随所属业务，公共 `PageResult` 等留共享目录。
3. `types/index.ts`、旧 API 文件可临时定向 re-export，记录剩余调用；迁移完成删除兼容出口，不能长期存在两份实现。
4. 避免大而全的 `export *` 入口让首页间接加载 Monaco 或所有业务页面。Monaco/Prism 分包必须做生产构建后的冷启动验证。
5. 路由表拆成前台/后台/考试等静态分组；守卫独立测试。导航元数据可共享名称和权限，但导航结构不必机械等同于路由结构。

## 5. 样式和死代码清理规则

继续保留当前黑白、直角、白底代码块的视觉风格。本次结构重构不同时重设计 UI。

- 先整理现有 `style.css` 的 token、基础元素、通用按钮/输入框、正文排版；明确一个视觉规则的所有者。
- 页面只保留布局和专用样式；先用一对页面验证共享按钮、筛选栏、状态提示，再逐页替换。
- 不把各页面的 `.header/.title/.panel` 直接搬成全局同名选择器，避免覆盖关系变化；可以使用组件作用域或业务前缀。
- `AdminLayout.vue:484` 附近使用深层选择器与 `!important` 覆盖页面类名，布局壳和业务页面已经耦合。先将重复的页面头/筛选栏样式迁移到有明确所有权的组件，再逐条移除覆盖；不能先删覆盖让布局失效。
- 重复颜色、字号和间距先归并为语义变量；确实有不同语义的危险操作、主按钮与次按钮保持区别。
- 保留用户已经确认的掉落动画、乱码复原、减少动态效果偏好，以及 100% 缩放下检索器的滚动与分页可见性。

可直接验证的样式试点：全局 `style.css:366`、`:384` 与算法/考试结果页的 loading 样式；`AdminQuestionsView.vue:251` 与 `AdminDbQuestionsView.vue:224` 一带的页面头、筛选和操作区域。先比较 DOM、尺寸、状态语义，再决定共用组件或共享样式，不以 CSS 看起来相似作为唯一依据。

删除前使用「引用证据 → 路由/动态使用检查 → 构建与交互验证」流程。`AppHeader.vue`、`questionApi.exportTestCasesZipUrl` 等静态搜索未发现调用的对象只能先列为候选，不能仅凭搜索结果删除。组件自动注册、动态 class、样式副作用、懒加载和类型声明都要检查。

`ComingSoonView.vue` 仍被路由动态导入，不能按文件名判定为残留。已有 `FormField`、`useConfirm/useToast`、`clipboard`、`sqlSchemaParser`、`userCache` 应优先扩用，避免建立平行工具。Markdown 的专用 CSS 与全局 `.prose` 要一起做级联验证。

先迁移调用方，再删除旧实现和失效样式；同一提交保留 Git 可恢复记录。不能根据文件名相似就删除两份侧栏测试，先确认各自覆盖的菜单行为与路由权限测试是否重复。

## 6. 实施批次与验收

| 批次 | 交付范围 | 关键验收 |
| --- | --- | --- |
| 0：建立基线 | 记录当前未提交改动、路由/截图/构建清单；补关键行为测试 | 当前正常行为与既有缺陷分开记录，不把用户改动覆盖掉；未提交的新功能（如进行中的题解模块）须先独立闭环或建立 stash/分支隔离，确保重构在稳定代码基线上启动 |
| 1：请求基础设施 | 合并刷新流程、统一下载错误处理 | 刷新成功/失败/退出竞争；Zip、Word、PDF 行为一致 |
| 2：列表试点 | 算法题、数据库题后台列表接入公共查询能力；下一小批迁移三个候选检索入口 | 快速输入、跨页、迟到响应、删除最后一项、权限与题型限制正确 |
| 3：判题试点 | 普通算法/SQL 结果页先接入，再迁移考试结果页 | 状态一致、轮询不重叠、不串提交、不丢上下文 |
| 4：业务页面拆分 | 先 Profile/后台编辑，再课练与考试会话 | 草稿、自动保存、截止交卷、题型差异、进度统计不变 |
| 5：视觉与目录收尾 | 统一公共样式；完成各 feature 路径迁移；删除确认残留 | 冷加载、所有深链接、视口回归、旧入口无引用 |

每批单独提交、单独验收，可独立回退。预计约 8–12 个工作日为初步安排，其中考试/课练回归占比最高；实施后根据首个列表和判题试点的实际规模调整。时间不是上线承诺，不为了进度跳过验收。

每批最少执行：相关行为测试、全量 `npm run test:unit -- --run`、类型检查与生产构建、lint。若存在既有 lint/build 问题先记录基线，不能全局关闭规则或借机大规模格式化无关文件。

交互回归重点：

- 普通算法、SQL、客观题；题集进入与返回；课练/考试提交；题解阅读、发布和管理。
- USER/TEACHER/ADMIN 角色；过期凭据；请求失败；快速路由切换；并发保存。
- 390px 移动端及 1280/1440/1920px 桌面、100% 缩放，长标题和长代码。
- 本地生产构建预览，首次进入代码编辑器与 SQL/Java 代码块，无 `Prism is not defined`、worker 或 chunk 加载错误。
- 同一查询状态只触发一次主动加载；每个提交监控实例至多一个结果请求在途，组件卸载后不再调度。

## 7. 完成标准

1. 鉴权刷新、判题终态和下载核心处理各有一个实现来源，并有行为测试。
2. 公共抽取至少有两个真实调用方；页面不再复制已经迁移的旧实现。
3. 大页面按职责拆分，业务差异清晰，没有新增含大量模式开关的万能组件。
4. 重构前后路由、权限、接口请求结构、草稿兼容和已确认 UI 行为不变；有意修复缺陷单独列明。
5. 清理项有证据，兼容出口有删除终点；没有 `any`、忽略类型检查或关闭 lint 来掩盖迁移问题。
6. 记录构建产物和请求次数的前后对比。减少重复源码不能直接宣称提升服务端并发或让页面更快。

建议第一批只覆盖请求刷新与两个后台题目列表：收益明确、范围可控，形成验证过的模式后再推进考试和课练。
