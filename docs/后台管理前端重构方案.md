# KECE 后台管理前端重构方案

日期：2026-11-07 · 状态：首轮界面改造已部署，本地核心流程联调已通过，完整验收仍在进行。

### 本轮实施记录

- 后台导航按业务分组，增加窄屏抽屉与 Esc 关闭；移除静态“评测集群在线”文案，并补导航权限与交互测试。
- 三类题库列表共用后台专属列表壳，统一标题、筛选、重置、结果区和失败重试。题集、考试、课练、用户、题解与公告列表调整信息层级和可操作性。
- 题目、题集、考试、课练编辑页改进分区、检索和响应布局；提交监控、公告编辑与考务详情补充布局、直角和表单可访问性调整。
- 沿用现有请求和业务模块，尚未整套引入 Ant Design Vue。此轮为现有代码上的界面与交互改造，不等同于方案中的全部重构及验收完成。
- 本地检查：19 个测试文件、92 项测试通过；类型检查与生产构建通过。ESLint 无错误，保留未改动首页 `HomeView.vue` 的一条 `v-html` 警告；生产构建仍有 Monaco 大包警告。
- 浏览器检查了 390px 窄屏导航、网络失败重试入口和教师菜单。连接本地 MySQL 后，以只读方式验证编程题按 ID 检索和重置、题目编辑页加载、客观题直接跳到第 2 页、题集检索防重复，以及数据库题、考试、课练和提交监控列表加载。
- 使用独立的临时 MySQL 实例完成空库迁移，验证管理员导航、编程题创建和回读、测试点 ZIP 导入与导出内容、题集保存后恢复章节与题目、试卷保存后恢复分值、课练发起及逐题统计空状态。
- 本地联调使用已有后端构建包。带真实作答的成绩统计、考务导出、题解和用户管理的完整操作，以及依赖 Redis 和评测机的重判仍待验收。
- 2026-11-07 已发布前端版本 `20261107T063001158036Z`。已核对线上首页、后台直达链接和新版静态资源，并验证公开题库接口响应正常。发布前备份了旧入口，保留旧版静态资源。线上浏览器检查因导航超时未完成。

## 1. 目标与范围

在保留 KECE 现有配色和直角设计的前提下，重新设计后台布局、组件和全部业务页面，面向教师和管理员高频完成题库维护、组卷、课练和考务管理。参考 **Vue Vben Admin 5 的 Ant Design Vue 版本**，借鉴其后台导航、页面层级及表单/表格交互，同时针对 KECE 的题目、考试和评测流程设计专属工作区。

- 项目：[Vue Vben Admin](https://github.com/vbenjs/vue-vben-admin) · [Ant Design Vue 演示](https://ant.vben.pro/) · [官方文档](https://doc.vben.pro/) · [MIT 许可证](https://github.com/vbenjs/vue-vben-admin/blob/main/LICENSE)。
- 选型依据和对照项目见 [开源项目参考调研](./后台管理开源项目参考调研.md)。
- 本提案是参考其设计与交互，不代表已选择整套引入模板。是否引入 Ant Design Vue、具体版本和体积须在试点验证后确定。
- 重构覆盖 `/admin` 下后台页面；前台、后端 API、数据库和判题规则不在视觉重做范围内。登录状态、权限、接口和现有业务功能必须保持正确。

## 2. 项目现状与约束

目前后台有 10 个导航模块、约 27 个子路由，包含列表、复杂编辑、考务统计及详情；当前 `/admin` 进入题目列表，没有现成的真实仪表盘。后台顶栏显示的“评测集群在线”为静态文案，新设计不得将其当成实时数据。

项目现为 Vue 3、TypeScript、Vite、Pinia 和 Vue Router；尚未引入 Ant Design Vue。后台与前台共享部分请求、下载、样式和组件。如果直接删除全部前端共享代码，会影响前台登录、下载与答题。因此，**后台界面可以整体替换，但先盘点并锁定行为，按模块替换，最后删除确认无调用方的旧后台代码**。

## 3. 视觉方向与页面骨架

方向：**KECE 直角工业风教学管理工作台**。借鉴 Vben 的清晰侧栏、顶部工具栏、面包屑、内容区与标准组件层级；视觉上继承 KECE 现有黑白灰色系、方正几何、细线分隔与克制的状态色。保留 KECE 标识与产品名称，改善字号、间距、信息密度和状态反馈，而不是将后台换成 Vben 默认主题。

以下是原型和实施的硬约束，基于当前 [`frontend/src/style.css`](../frontend/src/style.css)：

| 设计项 | 保留与应用 |
| --- | --- |
| 基础配色 | 页面白色 `#ffffff`，工作区浅灰 `#f4f5f7`、悬停灰 `#ebeef2`；主文字 `#111111`、次级文字 `#555555`、分隔线 `#ced4da`。按实际界面验证对比度。 |
| 直角形状 | 卡片、表格、按钮、输入框、弹窗、标签和选择控件统一 `border-radius: 0`；图标保持统一风格。 |
| 操作层级 | 主要操作使用现有深色按钮与浅色文字；次要操作使用浅色底与边框。危险、成功等状态沿用现有语义色，不以色彩作为唯一标识。 |
| 材质与排版 | 保留细线、方正布局和克制阴影，使用现有中文系统字体栈；提高表格和表单可读性，不引入大圆角、渐变或玻璃拟态。 |
| 第三方组件 | 若试点采用 Ant Design Vue，须覆盖默认圆角与默认主题，使其符合上述规范；只在后台作用域生效，不改前台外观。 |

原型可在上述色系内调整层级、留白和密度，但不得擅自更换品牌色系或圆角体系。

```text
┌─────────────┬──────────────────────────────────────────┐
│ KECE 管理   │ 面包屑 / 当前页面             用户与返回前台 │
│             ├──────────────────────────────────────────┤
│ 概览（可选）│ 页面标题与说明                 主要操作     │
│ 题库管理    │ 搜索 / 筛选 / 重置                         │
│ 教学与考试  │ ┌──────────────────────────────────────┐ │
│ 评测与内容  │ │ 表格 / 编辑工作区 / 统计详情          │ │
│ 系统管理    │ └──────────────────────────────────────┘ │
│             │ 总数 / 分页 / 跳页                          │
└─────────────┴──────────────────────────────────────────┘
```

图为信息结构示意，不是最终视觉稿。侧栏分组可折叠；桌面优先照顾 100% 缩放下的 1280–1920px 常见宽度。窄屏优先保持操作完整：侧栏抽屉化、筛选折行、表格允许横向滚动，复杂组卷区变单列。普通界面正文建议 14–16px，控件与行高按键盘操作及可读性验证；加载、无数据、权限不足、网络失败和危险操作均有明确状态。

### 导航分组建议

| 分组 | 页面 |
| --- | --- |
| 题库管理 | 编程题、数据库题、客观题、题集 |
| 教学与考试 | 考试与组卷、随堂课练、考生答卷和成绩 |
| 评测与内容 | 提交监控、题解管理、公告管理 |
| 系统管理 | 用户管理；按已有角色显示可用入口 |

概览页仅在有可核验 API 时展示真实数据；无数据源则保留清晰的快捷入口和不可用说明，严禁编造数字。评测机状态复用真实状态接口，离线、加载失败或无权限不能显示在线。

## 4. 关键页面设计

### 4.1 题库列表

标题区展示页面名称、简短说明和「新建」。筛选区支持题号、标题、难度、状态及现有可用条件，提供搜索和重置；表格清楚区分标题、难度、状态、出题人与时间。行操作有明确的编辑入口和危险操作确认；支持分页、跳页、加载、空结果、失败重试及窄屏横向滚动。题号精确检索不得退化为仅在当前页过滤。

### 4.2 题目编辑和测试点

以基本信息、题目描述、语言与限制、测试数据分区；Markdown/代码编辑器保留预览和公式/高亮能力。测试点显示数量与公开样例，导入 Zip 时明确覆盖选项和风险；导出使用现有鉴权下载。长页面底部提供清楚的保存、取消和未保存变更提示。

### 4.3 题集与组卷

桌面双栏：左侧是章节或试卷结构、已选题和分值，右侧是按题型、题号、关键字检索的候选列表；检索和分页可见，长标题换行。中等窗口可上下排列或打开抽屉，确保 100% 缩放仍能操作。保留去重、章节排序、题型限制、分数规则和试题快照行为。

### 4.4 考试、课练与成绩

考试和课练列表突出状态、时间、人数及管理入口；编辑页按基本信息、规则、题目编排与发布检查组织。课练概览以横向条目展示逐题作答/通过人数、正答率及无作答状态；考生答卷明确成绩、题目、代码与导出入口。成绩、时间和状态以实际接口及权限为准。

### 4.5 提交监控、题解、用户与公告

提交监控支持原有三类提交、筛选、状态、详情和授权重判；题解支持管理员筛选、阅读、隐藏与恢复；用户角色与危险操作遵循后端权限；公告保留内容编辑、发布状态及确认。敏感删除和重判需明确作用范围，并处理冲突、失败与重复点击。

## 5. 工程实施策略

1. **基线与原型**：盘点页面、现有路由、API、角色和危险操作；制作桌面和窄屏的后台壳、题目列表、题目编辑、组卷器原型，先确认视觉方向。
2. **新后台基础层**：在后台作用域内建立 token、布局、菜单、表格、筛选、表单、弹窗及状态组件；评估选定 UI 库的依赖体积、版本兼容和无障碍。避免改变影响前台的全局样式。
3. **普通列表迁移**：题库、题集、考试、课练、提交、公告、题解、用户，逐页对照 URL、权限、筛选、分页和危险操作。
4. **复杂工作区迁移**：题目编辑与 Zip、题集编排、考试/课练组卷和成绩详情。继续使用经过验证的鉴权、下载、检索与业务逻辑，按需改造，不按文件名假设代码可以删除。
5. **验收与清理**：完整浏览器回归、权限和边界状态检查，确认无调用后删除旧后台页面及残留样式。分模块提交，保留可回滚版本；未通过验收的模块不切换。

建议先按 1 名熟悉项目的前端工程师估算 **3–6 周**；这是粗估，不是上线承诺。原型确认后按页面数量、现有测试和实际联调结果重新拆分；不含新增后端 API、重大业务变更或历史缺陷修复。

## 6. 验收清单

- 教师与管理员登录、菜单、路由、数据归属和无权限访问符合现有后端权限；前端菜单隐藏不代替服务端鉴权。
- 对照现有 URL、接口、操作与权限逐项验证：题号精确检索和分页、测试点导入/覆盖/导出、题集章节编排、考试/课练分值与题型、答卷与成绩导出、提交详情与重判、题解和用户管理。
- 验证空、加载、失败、重复提交、网络中断、长题目、无权限及未保存退出等状态；桌面与窄屏键盘操作、可见焦点、对比度和滚动不遮挡。
- 对照现有 KECE 配色和 `--radius: 0` 逐页检查；不得残留第三方组件的默认圆角、默认主题色或影响前台的全局覆盖。
- 单测与相关业务测试、lint、类型检查、生产构建通过；在隔离测试数据上完成浏览器操作验证。对照重构前后的包体、关键页面加载和常用操作响应，明确性能变化。
- 限定上线范围并保留已验证的回退版本；复制第三方代码或资源时保留相应版权及许可声明并核对独立依赖许可。

## 7. 待确认

此提案把 Vben 的 Ant Design Vue 演示作为布局和交互参考，**KECE 黑白灰配色与直角风格已确定保留**。后台界面全部重做，但不预先决定整套框架迁入。优先交付的页面和具体视觉细节，在原型评审时确认。
